# 配置先行：让 RAW 知道你的几何

SAXS 还原里最贵的一类错误是**沉默的错误**——RAW 不会因为"配置不是这一天的"而报错，它会给你一条形状正常、数值全错的曲线。这个 skill 只干一件事：在动手积分之前，把"当前会话的几何与掩膜是不是这套数据的"从假设变成**已核对的事实**。

## R — 原文 (Reading)

> 配置文件允许RAW将2D图像积分为1D散射曲线。为了实现该功能，首先需要对散射图像进行定心和校准，即确定光斑中心即样品到探测器的距离，然后需要对探测器的坏点及Beamstop进行遮盖（Masking），让这些点不参与数据积分过程。针对特殊实验样品，还可以设置水或玻璃碳作为绝对标度，或一个分子量已知的标样作为分子量标准。
>
> 出处：§3 RAW 程序配置文件

> 注意：任何时候要处理图像，都需要加载适当的配置！
>
> 出处：§3（原文加粗提示）

**自述（同一节的加粗规则 + 线站做法）**：

> 注意：任何时候要处理图像，都需要加载适当的配置！……在BL19U2进行实验之前，线站工作人员会将当前实验参数设定好，导入RAW程序。如果在自己的计算机上使用RAW程序，只需点击File-Load Setting，找到实验当天对应的cfg文件导入，即可完成程序的配置工作。

## I — 骨架 (Interpretation)

必须先把一件事分开：**积分需要的几何信息不在图像文件里**。

一张 tif 里有像素，没有"光斑在哪、样品离探测器多远"。这四类信息活在 `.cfg` 里：

1. **定心**：光斑中心落在哪个像素；
2. **校准**：样品到探测器的距离（与定心一起把像素坐标换算成 q）；
3. **掩膜**：哪些像素不参与积分（Beamstop 阴影、坏点）；
4. **标度（可选）**：水/玻璃碳的绝对标度，或已知分子量的标样。

由此得到三条推论，它们就是这个 skill 存在的原因：

- **配置与"实验当天/那台仪器"绑定，不与数据文件绑定。** 所以"用今天的数据、跑昨天的配置"是一个完全合法的操作序列——程序不拦你。
- **失败是沉默的。** 没有配置时 RAW 用的是会话里残留的（或默认）几何：曲线照出、形状通常也还算像样，错的是 q 轴的标定与坏点处理。你从图上看不出异常。
- **必须有一个主动探针。** 可靠的探针是标样：BL19U2 用山嵛酸银（周期 5.8 nm），它的一级峰落在 q = 1.076 nm⁻¹。峰位对得上 → 几何是对的；对不上 → 别往下做。

一句话判据：**"我凭什么相信现在的 q 轴？"——答不上来就先别积分。**

## A1 — 操作案例 (Past Application)

**1. 线站的标准做法：实验前把当天参数导进 RAW**（§3）

- 问题：几何/掩膜随线站状态变化，用户不该猜。
- 做法：线站工作人员在实验前设定好当天参数并导入 RAW；用户在自己机器上处理时，用 `File → Load Settings…` 找到"实验当天对应的 cfg 文件"导入（或双击控制面板文件选项卡里的 `.cfg`）。
- 结论：cfg 与"实验当天"一一对应。这是一条运维惯例——**它把最难的一步外包出去了**，换个环境就得自己补上。

**2. 把配置做成硬判据：标样峰位**（§3）

- 问题：怎么知道配置真的对？
- 素材：BL19U2 的 SAXS 标样是山嵛酸银（5.8 nm 周期，一级峰 q = 1.076 nm⁻¹）；探测器为 Pilatus 2M（1679×1475 像素，像素 172×172 µm）。
- 做法：拿当天标样帧做一次积分，看一级峰是否落在 1.076 nm⁻¹。
- 结论：把"我以为设对了"升级成"峰位在预期处"。像素数/像素尺寸只在需要反推几何时才用。

## A2 — 触发场景 (Future Trigger)

**用户会在什么情境下遇到这类问题**

- 把线站的 tif 拷到自己的电脑上处理，q 轴数值与文献差一个倍数、Rg 差 10 倍。
- 换了实验日（或换线站、换了探测器）的数据，不确定要不要重新加载 cfg。
- 曲线上 Beamstop 阴影区出现怪异的突起/负值，想知道是不是掩膜没生效。
- 刚打开 RAW 就准备 Plot，想确认一下有没有前置动作漏掉。
- 需要向别人解释"为什么同样的数据在这台机器上算出来的 Rg 不一样"。

**语言信号**

- 「RAW 里处理图像前要先加载什么文件吗？」
- 「我直接 Integrate 了，出来的 q 轴感觉不对／单位怪怪的」
- 「这个曲线怎么跟文献差 10 倍？」
- 「换了一天的数据，要不要重新导入配置？」
- 「beamstop 那块怎么遮掉？」

**与相邻 skill 的区别**

- 与 `reduce-saxs-frames-to-curves`：那条流水线的前提是"配置已就绪"。本 skill 只回答"就绪了吗、怎么确证"；一旦确证，就把用户交给流水线。
- 与 `assess-guinier-fit-quality`：Rg 不对有两个来源——**配置错（所有样品一起错、整条 q 轴系统性偏移）** vs **拟合取点错（单条曲线内 Rg 随区间跳动）**。本 skill 负责前者，后者归 Guinier skill。
- 与"教怎么自己标定一台仪器"：**不在本 skill 范围内**（原文也没有，它把这件事交给线站工作人员）。

## E — 执行步骤 (Execution)

1. **问清数据的出身**：哪里采的（哪个线站/自建台）、哪一天、什么探测器、有没有当天的 `.cfg`。
   完成标准：能说出一份"应该用哪个 cfg"的答案（哪怕答案是"没有"）。
   - 判停点：如果数据不是本线站的、也拿不到对应 cfg → 停在"联系线站或自行标定"，**不要**用默认几何继续积分；把"q 轴绝对值不可信"明确告诉用户。
2. **加载配置**：`File → Load Settings…` 选当天的 `.cfg`（也可以在控制面板的文件选项卡里双击该 `.cfg`）。
   完成标准：控制面板上显示的几何/标样信息与当天的实验记录一致。
3. **用标样把配置验成事实**：找当天标样（BL19U2 = 山嵛酸银）的帧 → 积分 → 核对一级峰是否在 **q = 1.076 nm⁻¹**。
   完成标准：峰位在预期处（几何正确）；或明确报告"峰位偏离多少"。
   - 判停点：当天没有标样帧 → 只能做**相对比较**，必须告知用户 q 轴绝对值未经验证；不要假装配置是好的。
4. **确认掩膜生效**：Beamstop 与坏点已被遮掉。
   完成标准：能指出掩膜是否生效、以及它对哪些 q 区间有影响（阴影区不应出现异常突起或负值）。
5. **移交**：配置确证后，转 `reduce-saxs-frames-to-curves` 走还原流水线。
   完成标准：把"用了哪份 cfg、标样峰位核对结果"作为一条记录带过去（后续的 Rg 报告需要它）。

## B — 边界 (Boundary)

**不要用的场景**

- 用户只是问"RAW 是什么／在哪下载／怎么装"——那是信息查询。安装一律优先用 SourceForge 上的预构建安装程序（Windows/macOS/Debian），没有对应版本才回源码编译；这条不构成 skill。
- 用户要的是**从零标定**一台陌生仪器／自建台——原文把这件事交给线站工作人员（"如有其他设置问题，请联系线站工作人员"），本 skill 不越界提供标定教程。
- 用户手上已经是 `.dat` 曲线（没有 2D 帧）：配置这一步没有操作对象，直接去 Guinier skill。
- 用户问 GNOM / IFT / Shape&Size / Bayesian MW / 3D 重建——本文只列了名称，本 skill 一概不覆盖。

**作者警告过的失败模式**

- **不加载配置就积分**（候选 `p4/ce01`）：程序不报错，结果全错。这是本 skill 的头号反例。
- **以为图像里带着配置**：换数据不换配置，属于"看起来什么都没做错"的操作。

**作者盲点（阶段 0 批判第 3、7 条）**

- 把配置外包给线站，隐含假设读者永远在最标准的环境里工作；离开该线站就断链。所以本 skill 的定位是"**确证与加载**"，不是"从零标定"。
- 文章说"RAW 会自动找最佳 Guinier 区域"时也没提"配置不对会让自动选区一起错"——配置错误的连锁范围比文章承认的大。

**容易混淆的相邻方法论**

- `reduce-saxs-frames-to-curves`：共用同一个文件选项卡与 Profiles 列表；区别是"配置是否就绪"由本 skill 判定。
- `assess-guinier-fit-quality`：都产出"Rg 可不可信"的结论，但一个查系统性偏移、一个查区间稳定性。

**术语**：本 skill 与另外两条 skill 共用的词典（配置、定心/校准、掩膜、积分、平均、扣减、星标、标样、q 与 q_max·Rg、n_min/n_max 与残差、.dat、绘图选项卡——每条写明"作者定义 / 与常识的差别 / 为什么重要"）见
`references/bioxtas-raw-glossary.md`。
