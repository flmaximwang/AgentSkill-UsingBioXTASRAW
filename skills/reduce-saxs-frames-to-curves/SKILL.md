# 把 20 张帧变成一条曲线（2D → 1D 的还原流水线）

这条流水线的形状是**降维 → 降噪 → 去背景 → 落盘**。四段各解决一个误差来源，也各在 Profiles 列表里留下一个可读的状态痕迹——于是"我做到哪一步了、有没有漏"是可以机检的，而不是靠记。

## R — 原文 (Reading)

> ③、在BL19U2线站，通常会从给定样本中收集约 20 张图像。要加载牛血清蛋白 (BSA) 样本的 20 个图像，首先选择文件 bsa10_0002_000xx.tif，其中 xx 的范围为 01 到 20。这些文件是从 10 mg/ml BSA 散射测量的。
>
> 出处：§4 第③步

> ⑦、使用"平均（Average）"按钮将收集到的所有散射曲线平均到一条曲线中。平均散射曲线应出现在Profiles列表的底部。文件名将以绿色显示，并以 A_ 开头，表示它是平均散射曲线。
>
> 出处：§4 第⑦步

> ⑨、接下来，需要从测量的蛋白质散射（实际上是蛋白质的散射加上缓冲液的散射）中减去缓冲液散射曲线。给平均的缓冲液文件标星，并选择平均的蛋白质散射文件，然后单击"Subtract"按钮。
>
> 出处：§4 第⑨步

> 注意：这会将它们保存为 .dat 扩展名。这是 SAXS 散射曲线的标准格式。
>
> 出处：§4 第⑩步注意

## I — 骨架 (Interpretation)

先把"这一步在消除什么误差"讲清楚，动作才有意义：

1. **积分（2D → 1D）**：探测器上是二维环，同一个 q 落在整圈像素上。环形（方位角）平均把"像素的统计涨落 + 各向异性"压成一条曲线。它消除的是**几何维度**，不是噪声。
2. **平均（多条 → 一条）**：同一样品在同样条件下连拍约 20 帧，随机噪声按 √N 下降（20 帧 ≈ 压到 1/4.5）。它消除的是**随机噪声**——但同时也**会掩盖**辐射损伤、流动不稳这类系统性漂移。所以平均之后必须单独看这条曲线（见 E 第 7 步），这是这条流水线里唯一一处"降噪与失真同源"的地方。
3. **扣减缓冲液**：测到的"蛋白信号"其实是 蛋白+缓冲液+毛细管+溶剂背景。扣掉匹配的缓冲液平均曲线，才得到净散射。扣减的双方都必须是**代表曲线**（各用单帧去减会把自己的噪声带进结果）。
4. **落盘 `.dat`**：曲线是交付物，2D 帧只是"能重做"的保险。

**流水线的状态机**（这就是"自检"的全部依据）：

| 信号 | 含义 | 对应段 |
|---|---|---|
| 背景变**蓝** | 已被选中 | 操作中 |
| **`A_`** + 绿色 | 平均曲线（蛋白一份、缓冲液一份） | 第 2 段产物 |
| **`S_`** + 红色 | 扣减后的净散射曲线 | 第 3 段产物 |
| 文件名前 **`*`** | 有未保存改动；`*` 消失才代表写盘 | 第 4 段完成 |

判据：**用户问"我做完了吗"时，答案是"看有没有 `S_` 且 `*` 已消失"，不是"我记得我点过"。**

## A1 — 操作案例 (Past Application)

**1. 10 mg/ml BSA 的 20 帧走完十步**（§4 ①–⑩，候选 `p3/a01`）

- 问题：手上是一批 2D 帧（`bsa10_0002_000xx.tif`，xx = 01…20），要拿到可交付的曲线。
- 做法：文件选项卡定位目录 → 打开 → 文件类型过滤设为 `TIF 文件 (*.tif)` → 多选 20 帧 → **Plot** 积分 → 在 Profiles 列表里选中文件（变蓝）→ **Average**（得到绿色 `A_` 曲线）→ 用眼睛图标**隐藏各单帧**，只留两条平均曲线 → 给缓冲液平均**标星**、选中蛋白平均文件 → **Subtract**（得到红色 `S_` 曲线）→ 全选 → **Save**（文件名前的 `*` 消失）。
- 结论：一条曲线 = 若干帧 + 一次平均 + 一次扣减 + 一次落盘；缺任何一步都不算完成。
- 结果：产出 `.dat` 曲线（SAXS 曲线的标准格式）。作者另提示：图像被积分后通常只用曲线文件，保留图像只是为了**重新处理**。

**2. 为什么必须"隐藏单帧"**（§4 第⑧步，反例 `p4/ce03`）

- 问题：20 多条单帧曲线叠在同一张图上，目视无法判断平均曲线是否异常（小 q 上扬、掉点、负值都被淹没在"面条"里）。
- 做法：单击文件名左侧的眼睛图标，逐个隐藏（有斜线 = 隐藏），只留两条平均曲线。
- 结论："能看见"与"看得清"是两件事，需要主动做减法；这一步是平均能否被检查的前提。

## A2 — 触发场景 (Future Trigger)

**用户会在什么情境下遇到这类问题**

- 线站刚下机，手上是一批 tif/cbf，要产出给下游（ATSAS 等）用的曲线。
- 已经做过一轮，但不确定"有没有漏扣缓冲液／有没有保存"。
- 想确认"平均了 20 帧是不是就够了"、要不要剔帧。
- 曲线已经出来了，但下一步（读 Rg、发论文用图）之前想要一个"交付前检查"。
- 换了一台机器重做同一批数据，想知道产出物该是什么。

**语言信号**

- 「这批 tif 怎么变成一条曲线？」
- 「Buffer 要先处理吗／怎么扣缓冲液？」
- 「A_ 和 S_ 是什么？文件名前面那个 * 是什么意思？」
- 「我平均完就可以用了吗？」
- 「我要交给 ATSAS 的文件是什么格式？」

**与相邻 skill 的区别**

- 与 `configure-bioxtas-raw-for-a-dataset`：那条负责"配置是否就绪/怎么确证"。本 skill 的第 1 步就是"确认配置已加载"，**没就绪就转过去**，不在这里凑合。
- 与 `assess-guinier-fit-quality`：本 skill 到"一条扣减过的曲线"为止；**曲线物理上可不可信**（Rg、寡聚态、适合哪种分析）不在本 skill。
- 与 SEC-SAXS 处理：**连续洗脱的系列数据走 `process-sec-saxs-series`**（Series 选项卡、色谱图、"哪一段是一个物种"的平台判据），不要用批次平均的判据去套。

## E — 执行步骤 (Execution)

1. **确认配置已就绪**：本会话加载了当天 `.cfg`，或已用标样核对过峰位。
   完成标准：能说出"用的是哪份 cfg"。判停点：不确定 → 转 `configure-bioxtas-raw-for-a-dataset`，**不要继续**。
2. **定位数据**：文件选项卡 → 文件夹按钮 → 选中目标目录 → Open。
   完成标准：文件浏览器里能看到目标帧。
   - 提示：目录内可用 `..` 向上、双击进入；文件类型过滤器按探测器设（BL19U2 是 `TIF 文件 (*.tif)`）。
3. **选帧**：`Ctrl` + 单击多选，或单击起点再 `Shift` + 单击终点选区间；按惯例取同一样品的一批帧（BL19U2 约 20 张）。
   完成标准：选中帧数与实验记录一致，且**全是同一个样品的**。
   - 判停点：帧数明显偏少、或混入其它样品/其它浓度 → 先跟用户核清再积分。
4. **积分**：点绘图按钮（Plot）对全部选中帧积分。
   完成标准：Profiles 列表里出现与帧数一致的曲线文件，图上是多条曲线。
5. **平均**：在 Profiles 列表里选中该样品的全部曲线 → **Average**。缓冲液帧同样处理，得到它自己的 `A_` 曲线。
   完成标准：列表底部出现两条绿色 `A_` 曲线（蛋白一条、缓冲液一条）。
6. **隐藏单帧，单独检查平均曲线**：用眼睛图标隐藏除这两条 `A_` 曲线外的全部文件。
   完成标准：图上只剩两条曲线，能目视判断走向（是否小 q 上扬、掉点、负值、明显漂移）。
   - 判停点：平均曲线明显异常 → 回头逐帧检查是否有坏帧/辐照损伤（**作者未讨论剔帧，这一步是蒸馏者补的边界**），并把"是否平均了不一致的帧"作为结论告诉用户。
7. **扣减**：给**平均缓冲液**文件标星，选中**平均蛋白**文件 → **Subtract**。
   完成标准：列表里出现红色 `S_` 曲线；图上扣减结果在小 q 处回到合理形状（不应出现整段负值）。
   - 判停点：出现 `S_` 但形状明显反向（整段负值）→ 星标/选中角色给反了，交换后重做。
8. **落盘**：选中要交付的曲线 → **Save** → 选目标文件夹。
   完成标准：文件名前的 `*` **消失**；目标文件夹里出现 `.dat` 文件。`*` 还在就说明没写出去。
9. **归档记录**：写入"曲线文件名 + 帧数 + 用过的 cfg/配置版本 + 标样核对结果"。
   完成标准：别人（或三个月后的自己）能凭这条记录复现这条曲线。

## B — 边界 (Boundary)

**不要用的场景**

- 手上已经是 `.dat` 曲线（没有 2D 帧可还原）→ 直接去 `assess-guinier-fit-quality`。
- **SEC-SAXS**：连续洗脱的系列数据走 `process-sec-saxs-series`（Series 选项卡 + 色谱图 + 平台判据），本 skill 的"批次平均"逻辑不适用；扣减后仍有基线漂移时再转 `correct-sec-saxs-baseline`。
- **IFT/GNOM、Shape&Size、Bayesian MW、3D 重建、与 PDB 对齐**：本文只列了名称与一个外链（`bioxtas-raw.readthedocs.io`），没有流程与判据——不要拿本 skill 当这些事的指南（反例 `p4/ce05`）。
- 用户问的是"这条曲线说明我的蛋白是什么状态"——那是分析层，不是还原层。

**作者警告过的失败模式**

- **不加载配置就积分**（`p4/ce01`）：程序不报错，曲线全错。见本 skill 第 1 步的判停点。
- **不隐藏单帧**（`p4/ce03`）：平均曲线被埋在曲线丛里，异常看不见。
- **不保存就清理**（`p4/ce04`）：未保存的曲线只活在当前会话里；判断能否安全删除的唯一信号是 `*` 是否已消失。
- **流程走完但结果被下游拒**（盲测暴露的边界）：若"扣减完了、曲线看着还行，但下游说不能用"，**先用本 skill 的状态机自检**（有没有 `S_` 前缀 = 扣减是否成功、`*` 是否消失 = 有没有真的写盘、是否混入坏帧），**不要先跳到配置排查**；只有自检全过、曲线本身仍异常时，才回 `configure-bioxtas-raw-for-a-dataset` 查几何。
- 另一个容易踩的坑（跨 skill）：Subtract 的**角色由星标决定**，不是由文件名决定（术语 `g06`、`g07`）。

**作者盲点（阶段 0 批判第 4、5 条）**

- 文章把"每个样品约 20 帧"当惯例描述，**完全没有讨论要不要剔帧、怎么发现辐射损伤/流动不稳**。本 skill 只能把这一点显式标成"用户必须自己判断的缺口"，不能假装流水线自带质检。
- 文章把"配置已由线站设好"当前提；自己做数据的人要自己补第 1 步（跨到 `configure-bioxtas-raw-for-a-dataset`）。
